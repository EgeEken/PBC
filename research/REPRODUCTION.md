# Reproduction and dependencies

Pass 8 update: the existing private benchmark start route now validates `research_pass8/hf_release_job.py`'s fixed release/development comparison. With explicit operational authorization, `python research_pass8/run_hf.py benchmark` submits 20 allowlisted main images × four presets × two sources × three repeats. It does not start implicitly from checkout or verification. `analyze_comparison.py` reduces the ignored saved response into `comparison_summary.json` and the speed/RD/per-image tables. The current release modules remain immutable under `research_pass1/release/`; the root model matches the immutable model blob. HF and local numerical environments remain distinct. See `research_pass8/README.md` and its benchmark/UI reports for exact provenance, database backup and deployment commands. Historical Pass 5/6 authenticated specifications are no longer the server's active comparison API; their isolated local scripts remain archived.

Pass 6 runtime integration is active. Use `research_pass6/worker.py --source baseline` for the preserved pre-integration control and `--source integrated` for the current codec; these are isolated processes, with the same source model and input convention. `research_pass6/check_integration.py` verifies the saved 100-case local archive plus focused edge/concurrency tests. Its archive path refers to the original local HF checkout. The existing authenticated server now uses `research_pass6/hf_runtime_job.py` and its current manifest. Historical Pass 5 source manifests intentionally describe the old source and must not be substituted for this new worker.

The code is present for review without shipping image datasets or generated evidence. This setup does not run experiments. Keep results outside commits.

For the recorded local research environment, use Python 3.13 and `python -m pip install -r requirements-research.txt`. This pins the numerical packages recorded for Pass 1–5; the headless OpenCV wheel provides the same `cv2` import. Linux/HF Pass 5 used Python 3.11.17, NumPy 2.4.6, Numba 0.68.0 and Pillow 11.3.0. Do not assume Windows and HF trajectories are byte-identical. `research/environments.json` records both environments.

The unchanged `requirements_docker.txt` and Dockerfile describe the deployed server, including FastAPI, image codecs and Torch for its existing training UI. `train_api.py` and the tracked `pbc3_rl_a20.py` are included because the existing server references them; unrelated local RL/distillation scripts and training artifacts are excluded. Optional historical HF operations additionally require `huggingface_hub`. None is executed here. The inherited GitHub PDM files are historical metadata and do not define the HF or recorded research environment; use the requirements above for these experiments.

The existing production model is already included. Restore image inputs from the original local HF checkout, using `python research/prepare_assets.py --source "PATH_TO_ORIGINAL_HF_CHECKOUT"`. It checks all 25 image hashes before writing, refuses differing existing destinations and copies only declared ignored dataset inputs. It does not fetch from the network, train, encode, modify a model, or copy secrets. Dataset identity and source/model hashes are recorded in `research/assets.json` and `snapshot_manifest.json`.

The deployment-compatible runtime entry point is `research_pass5/hf_runtime_job.py`. Its static variants are `baseline`, `all_mse` (grid/search with internal metric), and `all` (grid/search with skipped metric). The original worker validates source/model/input hashes and uses one pinned CPU, numerical threads of one, full warmups, interleaved calls, independent decoded RGB scoring and stream/pixel equivalence. A future local invocation can pass the same JSON spec recorded in the Pass 5 report. Do not interpret local output as HF timing.

For the frozen allocator, `research_pass3/representation.py:select` is the actual selector, and `research_pass4/variants.py` installs it with weight 0.4 under the `alloc` variant. Required modules include the root `learned_filler.py`, `pbc3_ops.py`, `research_pass2/{common.py,runner.py,stream_tools.py}`, `research_pass3/{support.py,representation.py}` and `research_pass4/{support.py,runner.py,variants.py,allocator_cost.py}`. All are included. `python research_pass4/runner.py --worker current` accepts line-delimited JSON requests from the historical harness; it can execute explicit fresh input/config jobs without loading old aggregate archives. The frozen candidate uses Quality, `auto_downsample_max_pixels=500000`, `patch_count=35`; keep its seed/model/selector fixed for comparison. Cache modes remain distinguishable and unpromoted.

Historical plan generators, parsers, diagnostics, plotting and report scripts are retained verbatim. Their old READMEs describe the original full archive, including files deliberately excluded here. Many historical analysis/report/final-integrity commands require original raw rows, frozen streams, original absolute paths, or historical Git HEAD/status. They are not fresh-clone smoke commands. Restore the original local archive or regenerate fresh evidence under distinct output names before using those commands. `research/evidence_catalog.json` identifies important omitted evidence by hash. `runtime_source_manifest.json` path keys are normalized to POSIX separators; source algorithm files are unchanged apart from line endings. Historical decision JSON omits unrelated working-tree snapshots while retaining decision parameters/reasons.

`python research/verify_snapshot.py` performs only file/hash and Python syntax checks. It does not import codec modules or run benchmarks. This is the validation used for branch publication. The optional legacy `old_pbc.USE_NUMBA_RESAMPLE` path references a file absent in the original checkout; it remains disabled, and the unchanged default PIL path is the reference. No replacement is invented.

Archived deployment/commit/secret scripts under `research_pass5/` are source for operational review, not instructions to redeploy. Running them needs separate explicit authorization. GitHub branch publication grants no HF write/secret/restart permission. Public UI metric computation stays enabled; global monkeypatches must not be installed into a concurrent server.
