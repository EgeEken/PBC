# PBC 3.1 release readiness

## Artifact

The standalone Python package is staged at `dist/PBC3_1_Release.zip` (ignored output; not in Git history). Package metadata reports PBC 3.1.0. It preserves `PBC3.VERSION == 0`; no new bitstream version is claimed. Its per-file SHA-256 manifest is `PBC3_1_Release/PBC31_RELEASE_MANIFEST.json` inside the ZIP, and the archive checksum is in `dist/PBC3_1_Release.zip.sha256`: `dc069a075836040d45cf7a6375dd3603cb2d3ce0b3f1392784498b68ee522084` (129,366 bytes).

The package contains the codec runtime modules, `patch_policy.npz`, `README.md`, `CHANGELOG.md`, MIT `LICENSE`, exact dependency pins, `pyproject.toml`, and a command-line round-trip example. Module imports are package-relative. The default learned-model path resolves beside the installed package instead of depending on the caller's working directory. No server, frontend, benchmark database, training code, experiment, cache, dataset, or old codec copy is packaged.

The packager refuses to run if the runtime source or model SHA-256 differs from the frozen baseline. It records frozen source `8006f30debfc4a57289df06df21636aeb52baffd`, HF baseline `98ade0c8072a4571e9674eaac3d91f861e3b9867`, immutable PBC 3.0 commit `2e59f1b06980aa467da0cde94fa33c3f9a0d4d51`, and original model SHA-256 `ffaf24aa5447b3602c53a5c4c8df14a68ee16e6bded39331d973f38d0f1ea62f`.

## Validation

`release_smoke.py` extracted the ZIP into a fresh temporary directory, installed it with pip into a separate target, and ran it with a different temporary working directory. Python 3.11.16 and the pinned runtime dependencies were used. The check verified package imports, package-relative model loading, all four preset factories, valid v0 output, internal MSE, same-runtime repeat determinism, RGB and RGBA round trips, and decoding a v0 file generated by the immutable PBC 3.0 runtime. Quality encoding of `hpt_data/cat.jpg` reproduced the frozen reference stream SHA-256 `a4e1756ebae5e0ea61cf1dc9601565a6728a80a3388b24b09c3aed569110ac27`.

A 32×24 synthetic RGB stream was sent to the deployed Space's read-only `/api/decode` endpoint. Its returned pixels matched the local decoder byte-for-byte (SHA-256 `9f163495b1708073f2ad16ab20229dd3c27f7fdc04db52b85a568fd158698462`). This is a small Linux/HF decoder smoke only; it does not validate remote encoding or deployment changes. Details are in `hf_decode_smoke_results.json`.

## Requirements and limits

The package requires Python 3.11 and pins NumPy 2.4.6, Numba 0.68.0, and Pillow 11.3.0. LZMA uses Python's standard library (`lzma`/liblzma). Pip resolves Numba's normal compiled runtime dependency, including llvmlite. No Rust or project-specific compiled extension is required.

Output is deterministic within the tested runtime and environment. PBC3 v0 decoding is portable in the tested Windows and HF Linux environments. Cross-platform encoder bitstream identity remains unverified: Pass 13 observed stream differences between Windows and HF Linux despite matching source, model, and input hashes. The package constrains Python to the validated 3.11 series; other Python versions were not tested.

## Publication status

The Python-only release ZIP is assembled and passed its smoke tests. No GitHub release, tag, HF update, or release asset replacement was made. The artifact is ready for publication review; the documented cross-platform encoder limitation should remain in release notes.
