# Reproduce Pass 3

Run from the repository root in the recorded Python environment. Run CPU jobs sequentially. All production modules/models/inputs and prior research are read-only controls. Every command below is local; none commits, pushes, deploys, restarts, trains, uploads, or calls an HF endpoint.

The benchmark worker, parser, summary and interpolation helpers are imported read-only from Pass 2. support.py redirects only their in-memory output location into research_pass3. runner.py adds experiment counters, optional component traces and a switch to avoid duplicate files for known-identical streams. No previous artifact is overwritten. Only changed algorithm streams and initial screen files are retained; exact-output runs link to protected frozen current files by hash.

1. `python research_pass3/runner.py initial` — fresh output only; refuses to overwrite the initial snapshot and verifies Pass 2's manifest.
2. `python research_pass3/integration_patch.py`; `git apply --check research_pass3/proposed_grid_io.patch`; `python research_pass3/integration_checks.py`; `python research_pass3/performance.py correctness`.
3. `python research_pass3/performance.py screen_plan`; `python research_pass3/runner.py performance_screen`. The original exploratory screen used direct grid functions; full confirmation uses the exact proposed dispatch module.
4. `python research_pass3/patch_study.py`; `python research_pass3/analysis.py static_study`.
5. `python research_pass3/rate_plans.py fixed_identity`; `python research_pass3/runner.py fixed_identity`; then the corresponding fixed_screen plan/run. Identity must match every ordinary stream.
6. Review integrated_decision.json, then `python research_pass3/rate_plans.py integrated_screen`; `python research_pass3/runner.py integrated_screen`. The frozen rate weights are 0.1/0.4/0.8; no entropy ranking or extra model proposals.
7. `python research_pass3/search_plans.py search_exactness`; `python research_pass3/runner.py search_exactness`; `python research_pass3/search_compatibility.py`. Run search_screen only after intermediate/file exactness. The initial search screen excludes prototype scope installation; the final implementation charges per-call setup inside compress and has a separate search_setup_screen plan.
8. Review/freeze the retained promotion plans before confirmation. `python research_pass3/performance.py full_plan`; `python research_pass3/runner.py performance_full`; `python research_pass3/promotion.py`; `python research_pass3/runner.py allocation_full`.
9. `python research_pass3/runner.py search_setup_screen`, then search_full, then search_profile. These read fixed plans. Only rectangle reuse is promoted; the score-sharing approach is not additionally fully benchmarked.
10. `python research_pass3/auxiliary.py memory`; `python research_pass3/auxiliary.py startup`; `python research_pass3/prepare_hf_manifest.py`.
11. Portable-package local smoke: `python research_pass3/hf_cpu_benchmark.py --smoke --repeats 2 --label LOCAL_PACKAGING_SMOKE --output research_pass3/hf_plan_smoke`. Choose a new output directory for a new run; the helper refuses to overwrite it. It uses only local repository inputs. Its name does not make its timings HF evidence. Full runs are reserved for a later explicitly authorized HF validation.
12. `python research_pass3/analysis.py performance`, allocation, traces and trajectory_comparison; `python research_pass3/plot.py`. conclusions.json records the final interpretation after reviewing measurements. Run `python research_pass3/report.py`, then `python research_pass3/final_checks.py`.

Re-running a Pass 3 command overwrites its own Pass 3 output names, so preserve this directory first for an independent run. Plans include this checkout's absolute input paths; update those explicitly if relocating. The portable HF harness has a separate POSIX-relative source/input manifest and no dependency on Pass 1/2 benchmark scripts. It validates source/model/input identity and pins both isolated source workers to the same allowed CPU.

JSON/JSONL is authoritative for expanded configs, hashes, module inventories, patch signatures, counters and raw repeated timings. CSV keeps scalar columns. Timing summaries average per-case medians and also retain actual-call means/CV. Primary metrics use actual decoded original-size RGB; opaque/nonopaque alpha and result.mse=None behavior have separate checks. Raw bytes include the six-byte outer wrapper. Prefix marginal final bits are nonadditive entropy-context observations, not ownership of compressed bytes by a patch.

Required reports: PBC_PERFORMANCE_INTEGRATION.md, PBC_RATE_AWARE_ALLOCATION.md, PBC_SEARCH_REUSE.md and PBC_PASS3_SUMMARY.md. The summary explicitly answers all 20 questions. changed_files.txt and artifact_manifest.json enumerate created artifacts and hashes, excluding caches. final_validation.json verifies protected prior artifacts, source/model/dataset integrity, deterministic repeats, saved streams, exact optimizations, geometry ablations, quantized arrays and unapplied-patch applicability.
